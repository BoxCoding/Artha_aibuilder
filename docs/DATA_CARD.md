# Data card

## What the prototype runs on

100% synthetic bank statements, generated by `app/synthetic/generator.py`. No real customer, account,
bank or transaction appears anywhere in this repository or in any demonstration of it.

Bank names ("Kaveri Commercial Bank", "Northstar Bank") are invented. Account holders are invented.
Account numbers are masked to four random digits. Amounts, counterparties and dates are generated from
seeded random distributions.

## How statements are built

A `Profile` describes a business — income mix (UPI, bank transfer, cash), supplier payment ratio, rent,
utilities, staff costs, existing instalments, seasonality. The generator produces six months of daily
transactions, computes a running balance, and renders a multi-page PDF with a realistic header, column
layout and per-cell fonts.

Tampering is applied deliberately and **labelled**, which is what makes the evaluation meaningful:

| Pattern | What it does | What should catch it |
| --- | --- | --- |
| `inflate_row_only` | Raises large deposits, edits only that row's balance | Balance reconciliation + font outlier |
| `inflate_recomputed` | Raises deposits and repairs every later balance | Font outlier alone |
| `editor_resave` | Re-saves through a simulated online PDF editor | Producer string, incremental update, date skew |
| `injection` | Inserts a narration addressed to an AI reviewer | Injection detector |

`random_population(n)` produces a mixed population — roughly half clean, half carrying one pattern —
with ground-truth labels, which is what the evaluation suite measures against.

## Personal data handling

The pipeline is built as if the data were real:

- **Consent** is captured before analysis with a versioned notice, timestamped on the case.
- **Masking**: email addresses, PAN-format strings, 12-digit identifiers, phone numbers and long digit
  runs are masked before any text enters a model prompt or a log line.
- **Redaction**: narrations containing instructions aimed at an automated reviewer are replaced with a
  placeholder before any model call.
- **Minimisation**: the memo bundle carries only transaction rows actually referenced by a finding, plus
  computed aggregates — not the full statement.
- **Role shaping**: borrower API responses are built by a separate projection that contains no scores,
  signals, features or evidence, so internal analysis cannot leak through a field added later.
- **Audit**: every access and decision is written to a hash-chained log holding a hash of the detail
  rather than the detail itself.

## Retention

The prototype keeps cases in memory with LRU eviction and loses everything on restart. A real
deployment needs a documented retention schedule, deletion on request, and encryption at rest with
customer-managed keys.

## Known gaps

No real statements have been tested. No account-aggregator integration exists. The Gemini extraction
path for scans and unusual layouts is implemented and schema-validated but is not represented in the
evaluation numbers, because the generator only produces clean text-layer PDFs.
